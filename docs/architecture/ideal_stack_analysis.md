# 🔬 Глубокий анализ и обоснование идеального технологического стека GupkaCommander

> [!NOTE]
> **Назначение документа:** Комплексный инженерный анализ и спецификация эталонного технологического стека для локального ИИ-ассистента операционной системы Windows 11 с голосовым и чат-управлением. Документ содержит сравнительный анализ альтернатив, расчет бюджета памяти и аппаратных ресурсов (RTX 5050 8GB VRAM / i5-14450HX / 16GB RAM) и архитектурные инварианты.

---

## 1. Аппаратный контекст и граничные условия

Для устойчивой работы локального ассистента без вылетов и деградации системы определен жесткий ресурсный бюджет:

| Ресурс | Всего | Выделено под ОС и фоновый софт | Доступно ассистенту | Лимит безопасного использования |
| :--- | :--- | :--- | :--- | :--- |
| **VRAM (RTX 5050)** | **8 151 МБ** | ~800–1 000 МБ | ~7 100 МБ | **$\le$ 5 500 МБ** (запас под буферы экрана и видеопамять Windows) |
| **RAM** | **16 384 МБ** | ~6 000–8 000 МБ | ~8 000 МБ | **$\le$ 3 500 МБ** (пиковая нагрузка всех процессов ассистента) |
| **CPU (i5-14450HX)** | **10 ядер (16 потоков)** | Базовые службы | 60–80% вычислительной мощности | Параллельные потоки STT, TTS, VAD и GUI |

## 2. Сравнительный анализ и выбор стека по подсистемам

### 2.1. Когнитивное ядро (LLM & Vision-Language Model)

#### Сравнение подходов:
1. **Подход 1: Раздельные модели (Текстовая LLM + Модель детекции иконок)**
   * *Стек:* `Qwen2.5-7B-Instruct` + `OmniParser v2` (YOLOv9 + Florence-2).
   * *Плюсы:* Высокая точность парсинга мелких иконок Windows.
   * *Минусы:* Две тяжелые модели в VRAM ($4.5\text{ ГБ} + 1.8\text{ ГБ} = 6.3\text{ ГБ}$). Занимает 80% видеопамяти, создает задержки при переключении контекста, сложный пайплайн координации.
2. **Подход 2: Единая компактная мультимодальная модель (SOTA GUI Grounding)**
   * *Стек:* **`Qwen2.5-VL-3B-Instruct` (квантование Q4_K_M)**.
   * *Плюсы:*
     * Нативная поддержка динамического разрешения и точных экранных координат.
     * Потребление VRAM: **всего ~2.4–2.8 ГБ**!
     * Способна вести связный русскоязычный диалог, вызывать системные инструменты (Tool Calling) и визуально находить элементы на экране в рамках одной нейросети.
     * Скорость генерации: 45–60 токенов/сек на Tensor-ядрах RTX 5050.
   * *Минусы:* Требует четкого системного промпта с описанием доступных инструментов ОС.

#### Движок инференса (Runtime):
* **Выбор:** **`llama-server` (бинарный сервер из экосистемы `llama.cpp`)** либо встроенный `llama-cpp-python` с поддержкой `Qwen25VLChatHandler`.
* **Почему не чистый PyTorch / HuggingFace Transformers:**
  * Чистый PyTorch резервирует дополнительно 1.5–2 ГБ VRAM под служебные структуры CUDA кэша.
  * `llama.cpp` на C++/CUDA обеспечивает минимальный оверхед по памяти, квантование GGUF и отдает стандартный OpenAI-совместимый REST/SSE API (`http://127.0.0.1:8080/v1`).
  * Полная изоляция от Python runtime — исключает конфликты версий CUDA/cuDNN DLL с CTranslate2.

### 2.2. Голосовой контур (Voice Pipeline — 100% CPU Offloading)

Чтобы вся видеопамять оставалась доступна модели мышления и зрения, голосовой контур выносится исключительно на **CPU**.

#### Сравнение и выбор:

| Задача | Рассмотренные кандидаты | Финальный выбор | Обоснование |
| :--- | :--- | :--- | :--- |
| **VAD (Активность речи)** | WebRTC VAD, Silero VAD v5 | **Silero VAD v5 (ONNX CPU)** | Точность > 98% на шумном фоне, мгновенная задержка (< 3 мс на чанк), потребление CPU < 1%. |
| **STT (Распознавание речи)** | Vosk, Whisper.cpp, Faster-Whisper, Canary | **Faster-Whisper (`small` INT8, CPU)** | Движок `CTranslate2` на 4 потоках CPU расшифровывает 3-секундную фразу на русском языке за **180–240 мс**. Идеальная грамматика и пунктуация. |
| **TTS (Синтез речи)** | pyttsx3 (SAPI5), Edge-TTS, Coqui TTS, Piper | **Piper TTS (ONNX CPU)** | В отличие от Edge-TTS, работает **100% офлайн**. В отличие от SAPI5, звучит как живой диктор. Синтез 1 секунды речи занимает **~40 мс**. Модель: `ru_RU-dmitri-medium` или `ru_RU-ruslan-medium`. |
| **Аудио I/O** | PyAudio, sounddevice | **`sounddevice` (WASAPI)** | Нативная поддержка низколатентного Windows WASAPI, чистая работа в фоновых потоках без блокировок. |

### 2.3. Автоматизация операционной системы Windows 11

#### 4-уровневая структура исполнения:

1. **Tier 0: Fast-Path Resolver (Запуск программ, сайтов, консоли)**
   * **Поиск софта:** Сканирование разделов реестра `Uninstall` и `App Paths` + парсинг ярлыков меню «Пуск» (`.lnk`).
   * **Нечеткий поиск:** Библиотека **`rapidfuzz`** (C++ ядро). Время матчинга запроса «открой телегу» к `Telegram.exe` среди 500 программ занимает **0.4 миллисекунды**.
   * **Запуск программ и сайтов:** `win32api.ShellExecute` / `os.startfile`. Позволяет Windows самостоятельно разруливать запуск UWP, протоколов и ассоциаций без создания дочерних зомби-процессов.
   * **Консоль и терминал:** Запуск интерактивного Windows Terminal (`wt.exe`) или фоновое исполнение изолированных команд через `subprocess.Popen` с лимитом времени и фильтром опасных команд.
   * **Окна и система:** `pywin32` (`win32gui`, `win32con`, `win32process`) — мгновенный фокус окон, сворачивание, разворачивание, изменение системной громкости.

2. **Tier 1: Windows UI Automation (Семантический уровень)**
   * **Выбор:** Библиотека **`uiautomation`** (нативная обертка Microsoft UI Automation COM).
   * **Преимущество:** Находит кнопки, вкладки, поля ввода и списки по их программным идентификаторам (`AutomationId`, `Name`, `ControlType`). Позволяет вызывать `Invoke()` и `SetValue()` без физического перемещения мыши.

3. **Tier 2: Browser Bridge (Веб-уровень)**
   * **Выбор:** Легковесный коннектор к Chrome/Edge через **Chrome DevTools Protocol (CDP)** или преднастроенный профиль `playwright`.
   * **Преимущество:** Точный клик по ссылкам, заполнение поисковых строк на YouTube, GitHub, маркетплейсах без потери фокуса и без зависимости от разрешения монитора.

4. **Tier 3: Vision Grounding (Визуальный уровень)**
   * **Захват экрана:** Библиотека **`mss`** (прямой захват через Windows Desktop Duplication / GDI со скоростью > 60 FPS, < 15 мс на 1080p кадр).
   * **Проекция:** Учет DPI-масштабирования Windows (`ctypes.windll.shcore.SetProcessDpiAwareness(2)`).
   * **Эмуляция ввода:** `pyautogui` / `pynput`.

### 2.4. Графический интерфейс (GUI)

#### Сравнение альтернатив:
* *Electron / Tauri:* Избыточный оверхед (веб-движок Chromium потребляет 300–600 МБ RAM), сложный мост IPC между Node.js/Rust и Python.
* *Tkinter:* Устаревший внешний вид, отсутствие поддержки стилей Windows 11 и эффектов размытия.
* *Финальный выбор:* **`PySide6` (Qt 6 для Python)**.
  * Нативные C++ виджеты, аппаратное ускорение рендеринга.
  * Потребление оперативной памяти: всего **~60–80 МБ**.
  * Поддержка полупрозрачных эффектов Windows 11 (Mica / Acrylic) через библиотеку `pywinstyles` и вызовы DWM API.
  * Форм-фактор:
    1. **Spotlight Bar (Command Palette):** Центрированная плавающая строка (вызов по `Alt+Space`).
    2. **Voice Waveform Indicator:** Анимированная индикация громкости и фазы (слушаю/думаю/говорю).
    3. **Expandable Chat Drawer:** Выдвижное полотно диалога с историей шагов и рассуждений.
    4. **System Tray:** Управление в трее с цветовой индикацией статуса.

---

### 2.5. Безопасность и аварийный сброс (Fail-Safe Architecture)

1. **Аппаратный перехватчик аварийной остановки (Emergency Kill-Switch):**
   * Глобальный низкоуровневый перехватчик клавиатуры (`pynput.keyboard.Listener` в отдельном независимом демоническом потоке).
   * Клавиша `Esc`: мгновенно взводит глобальный флаг `abort_signal = True`, прерывает любые циклы эмуляции мыши, очищает очереди действий и отпускает зажатые клавиши/кнопки мыши.
2. **Mouse Shake Detector:**
   * Если пользователь резко дергает физическую мышь во время автономных действий агента (смещение > 350 пикселей за 100 мс), управление мгновенно возвращается человеку.
3. **Безопасность системных команд:**
   * Команды форматирования, рекурсивного удаления папок вне временных директорий, завершения критических процессов Windows блокируются до получения подтверждения через диалоговое окно GUI.

## 3. Матрица эталонного стека (Итоговая спецификация)

| Компонент | Выбранный инструмент | Роль и назначение | Устройство |
| :--- | :--- | :--- | :--- |
| **Пакетный менеджер** | **`uv`** | Сверхбыстрое управление виртуальным окружением, lockfile и зависимостями | CPU |
| **Язык разработки** | **Python 3.12** | Стабильные предсобранные бинарные колеса для PySide6, PyWin32, CTranslate2 | CPU |
| **Графический интерфейс** | **`PySide6` (Qt 6)** | Плавающий Spotlight-интерфейс, Mica/Fluent дизайн, системный трей | CPU/GPU (DWM) |
| **Голосовая детекция** | **`silero-vad` (ONNX)** | Выделение речи из шума, детекция пауз, триггер окончания фразы | CPU (< 1%) |
| **Распознавание речи** | **`faster-whisper`** | Локальная транскрипция русской и английской речи (INT8) | CPU (4 потока) |
| **Синтез речи** | **`piper-tts` (ONNX)** | Натуральная русская речь (< 50 мс задержка, оффлайн) | CPU (< 2%) |
| **Аудиодрайвер** | **`sounddevice`** | Захват микрофона и воспроизведение через Windows WASAPI | CPU |
| **Когнитивный мозг / VLM** | **`Qwen2.5-VL-3B-Instruct`** | Единая модель рассуждений, Tool Calling и координатного зрения (Q4_K_M) | **GPU (~2.6 ГБ VRAM)** |
| **Инференс-движок** | **`llama-server` / `llama-cpp-python`** | OpenAI-совместимый локальный сервер инференса GGUF с нулевым оверхедом | **GPU (CUDA)** |
| **Разрешение софта** | **Windows Registry + `.lnk` + `rapidfuzz`** | Мгновенный поиск любого установленного приложения (< 1 мс) | CPU |
| **Исполнитель ОС** | **`pywin32` + `subprocess` + `os.startfile`** | Нативный запуск программ, консоли, сайтов и манипуляция окнами | CPU |
| **Семантический UI** | **`uiautomation`** | Чтение дерева доступности Windows, клики и ввод по ID элементов | CPU |
| **Захват экрана** | **`mss`** | Сверхбыстрый захват кадра монитора (DXGI/GDI < 15 мс) | CPU/GPU |
| **Эмуляция ввода** | **`pyautogui` / `pynput`** | Плавное наведение курсора, клики и набор текста | CPU |
| **Аварийный сброс** | **`pynput` + Mouse Shake Filter** | Мгновенная блокировка по `Esc` и движению мыши | CPU |

## 4. Схема многопроцессной изоляции (Архитектурный инвариант)

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        MAIN COORDINATOR PROCESS                        │
│                                                                        │
│  ┌──────────────────────┐  PySide Signals   ┌───────────────────────┐  │
│  │    PySide6 GUI       │ ◄───────────────► │    Fast Router        │  │
│  │ (Spotlight, History) │                   │  (Intent & Fast-Path) │  │
│  └──────────────────────┘                   └──────────┬────────────┘  │
└────────────────────────────────────────────────────────┼───────────────┘
                                                         │
             ┌───────────────────┬───────────────────────┴───────────────┐
             │ Inter-Process     │ Inter-Process                         │ HTTP / SSE
             │ Queues (IPC)      │ Queues (IPC)                          │ Local REST
             ▼                   ▼                                       ▼
┌─────────────────────────┐ ┌─────────────────────────┐ ┌─────────────────────────┐
│     AUDIO PROCESS       │ │   OS EXECUTOR PROCESS   │ │   LLAMA-SERVER (GPU)    │
│                         │ │                         │ │                         │
│ • sounddevice (WASAPI)  │ │ • Fast-Path Runner      │ │ • Qwen2.5-VL-3B Q4_K_M  │
│ • Silero VAD (ONNX CPU) │ │ • uiautomation (UIA)    │ │ • CUDA Acceleration     │
│ • Faster-Whisper (INT8) │ │ • mss Screen Capture    │ │ • Port 127.0.0.1:8080   │
│ • Piper TTS (ONNX CPU)  │ │ • FailSafe Hook (Esc)   │ │ • Tool Calling Engine   │
└─────────────────────────┘ └─────────────────────────┘ └─────────────────────────┘
```

Такая изоляция гарантирует:
1. Зависание или ошибка модели никогда не повесит графический интерфейс.
2. Непрерывная запись звука не прерывается вычислениями или перерисовкой UI.
3. Библиотеки CTranslate2 и CUDA в инференс-сервере работают в полностью изолированных изолированных средах, исключая конфликты DLL.
